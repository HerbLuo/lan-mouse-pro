# 需求：用 QUIC 替换 webrtc-dtls + UDP，并支持剪贴板文本 / 图片 / 文件同步

## 1. 背景与动机

现状基于 `webrtc-dtls + UDP`，且**没有跨设备剪贴板同步功能**（README 中 Clipboard support 为 TODO）。

传输层局限：

| 问题                  | 触发场景           | 后果                       |
| --------------------- | ------------------ | -------------------------- |
| 应用层无 ACK / 重传   | UDP 丢包           | 按键、Enter/Leave 丢失     |
| 2 s idle 即断         | 对端暂停、GC、休眠 | 鼠标卡顿数秒               |
| 大文件 / 图片没有通道 | -                  | 传大文件会导致鼠标卡顿数秒 |

需求：用 **QUIC** 替换 `webrtc-dtls`，并在其上**新增**文本 / 图片 / 文件的跨设备剪贴板与文件同步。

## 2. 范围

**In Scope：**

- 传输层由 `webrtc-dtls` 替换为 QUIC（沿用现有自签证书 + 指纹白名单做对端认证）。
- 保留现有 IPC、CLI、GTK UI、主机名解析流程（`src/dns.rs`，依赖 OS 层 mDNS / Bonjour）。
- 新增三类同步：
  - 剪贴板 **文本**
  - 剪贴板 **图片**（PNG / JPG）
  - **复制文件** 跨设备同步

**Out of Scope：**

- 剪贴板格式协商（HTML、RTF 等）—— 首版仅 text + image + file。
- 文件断点续传（首版一次性成功）。
- CRDT / 最终一致性 —— 仍按"最后一个写入者赢"，但需避免回环。

## 3. 功能需求

### 3.1 传输替换

- 所有现有设备互通场景在切换到 QUIC 后行为不变：鼠标共享、键盘转发、Enter/Leave/Ack 同步、`Hello` 版本握手。
- 探活超时由 8 s 放宽到 ≥ 30 s。

### 3.2 剪贴板文本

- 本机剪贴板变化 → 同步至所有已配对对端。
- 大文本应能正确同步（不限 4 KiB）。
- 必须避免回环：本地写入后不要再把同一份内容广播回去。

### 3.3 剪贴板图片

- 支持从源端剪贴板读出图片并粘贴到对端。
- 支持常见格式（PNG / BMP）。
- 必须避免回环。

### 3.4 复制文件

- 源端复制一个文件，对端可接收并落盘。
- 接收行为可配置：默认**询问**（弹通知让用户确认），可设为**自动接收**。
- 必须校验完整性（SHA-256）。
- 源端取消复制时，对端应能终止正在进行的接收。

## 4. 验收标准

1. 鼠标移动 / 滚轮在 100 Mbps / 50 ms RTT LAN 下端到端 ≤ 16 ms（p99）。
2. 复制 1 MiB 文本 → 对端粘贴成功，无丢失、无重复。
3. 复制一张 4 K 截图 → 对端粘贴为 PNG，字节级一致。
4. 复制一个 200 MiB 文件 → 对端可选择接收，落盘后 SHA-256 一致；中途拔网后恢复能重传或清晰报错。
5. 现有 IPC、CLI、GTK UI 不需要改公共 API。
